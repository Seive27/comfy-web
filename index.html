Three layers. One framework.

Comfy Skill combines taste-driven design, structured skill graphs, and deterministic rendering into a single pipeline.

Comfy Layer

A design rules engine that constrains AI output to your brand. Colors, typography, spacing, and component choices are locked before generation begins. No surprises.

Skill Graph

Define capabilities as structured skills. Each skill knows its inputs, outputs, validations, and visual representation. The graph routes agent intent through deterministic nodes.

Deterministic Rendering

Same input always produces the same output. No hallucinated layouts, no drifting UI state, no surprise modals. Your interface stays predictable and testable.

How it compiles

From agent intent to production UI in four deterministic stages.

Parse

Agent Intent

Raw LLM output is captured and normalized into a structured intermediate format.

Validate

Taste Check

Every element is validated against your design rules. Non-compliant output is rejected.

Route

Skill Graph

Intent is routed through the skill graph, matching capabilities to deterministic component nodes.

Render

Deterministic UI

Final markup is produced from locked templates. Same input, same output. Every time.

How it works

The skill reads the brief first

Comfy Skill infers the right layout variance, motion, and density from cues like "minimalist", "editorial", "SaaS", or "portfolio", then picks the design direction.

0

Brief inference

Reads the page kind, vibe words, audience, references, and brand assets before any code. Declares a one-line design read instead of defaulting to AI-purple gradients and three centered feature cards.

2

Brief to design system map

When the brief reads as Material, Fluent, Carbon, Polaris, or Tailwind, the agent reaches for the official package. Aesthetic-only briefs are labeled honestly as web approximations.

5

Animation skeletons

Canonical code patterns for sticky-stack, horizontal-pan, and scroll-reveal stagger. Hand-rolled scroll listeners and rAF loops touching React state are out.

8

Dark mode protocol

Dual-mode by default. WCAG AA contrast, hierarchy parity, brand fidelity in both themes. Off-black and off-white, never pure values.

9

Big bans

Strict list of the patterns that make generated frontends look the same. The agent enforces these on every output.

11

Redesign protocol

Audit-first on existing projects. Greenfield, preserve, or overhaul mode. URL structure, nav labels, and form field names never change silently.

12

Block library schema

Schema for real, source-backed blocks: hero, feature, social-proof, pricing, CTA, footer, portfolio, transition, navigation.

14

Hard pre-flight check

Every checkbox must honestly pass before the agent ships. No box, no ship.

The Locks

Rules the agent never relaxes

Three rules keep a generated page visually coherent end to end.

C

Color Consistency Lock

One accent across the whole page. A warm-grey site does not suddenly get a blue CTA in section 7.

S

Shape Consistency Lock

One corner-radius system per page. All-sharp, all-soft, or all-pill, with a documented exception when mixing.

T

Page Theme Lock

Light, dark, or auto, picked once at the page level. No mid-page flips into a different theme.

Hero Discipline

Hard rules for above the fold

Headline Maximum two lines on desktop
Subtext Maximum twenty words and four lines
Primary CTA Visible without scroll
Navigation Single line at desktop, height maximum 80px
Anti-Slop Ban System

Patterns the agent enforces

The full list ships in the SKILL.md file. These are the most commonly triggered bans.

Em-dashes and en-dashes
Banned everywhere in output copy. Use a hyphen or restructure the sentence.
Section-numbering eyebrows
00 / INDEX, 001 - Capabilities. Eyebrows should name the topic in plain language.
Hero version labels
V0.6, BETA, INVITE-ONLY in the hero is banned unless the brief is explicitly a product launch.
Photo-credit captions as decoration
Real attribution to real photographers only. No fabricated credits.
Hero decoration text strips
BRAND. MOTION. SPATIAL. and similar mono-caps strips at the hero bottom are banned.
Scroll cues
Scroll, down-arrow icons, Scroll to explore. The user knows how scroll works.
Three-equal-card feature rows
Banned by default. Use 2-column zig-zag, asymmetric grids, or scroll-pinned alternatives.
AI-purple gradients
Banned by default. Neutral bases with one high-contrast accent. Override only when brand is explicitly purple.
window.addEventListener('scroll')
Banned in JS. Use Motion useScroll, GSAP ScrollTrigger, IntersectionObserver, or CSS scroll-driven animations.
Div-based fake product UI
No fake task lists, terminals, or dashboards built out of styled divs. Use real screenshots or generated images.

View the full ban list on GitHub

Skill Files

The repo bundles multiple SKILL.md files

Enable the ones that match your stack.

comfy-skill-frontend

Reads the brief, infers the right design direction, and ships interfaces that do not look templated. Brief inference, design-system map, complete em-dash ban, redesign-audit protocol, strict pre-flight check.

gpt-comfyskill

Stricter variant for GPT and Codex models with higher layout variance, stronger motion direction, and tighter anti-slop checks.

redesign-skill

Six-category site audit for upgrading existing projects. Finds generic patterns and guides fixes.

soft-skill

Calm, polished UI with softer contrast, more whitespace, and spring-style motion.

minimalist-skill

Editorial product UI inspired by Linear, with restrained palette and tighter hierarchy.

brutalist-skill

Swiss typography, raw structure, and sharper contrast for mechanical visual language.

output-skill

Anti-laziness rules for agents. Blocks placeholder comments, skipped sections, and half-finished output.

image-to-code-skill

Image-first pipeline: generate reference frames, analyze them, then implement the frontend to match.

imagegen-frontend-web

Image-only skill generating horizontal website section reference frames for handoff coding agents.

Customization

Edit the skill to match your brand

The SKILL.md file is fully editable. Open it in your project root and modify, add, or remove any rule to match your design direction. The agent reads the file on each run, so edits apply on the next generation.

* If you maintain a project-specific style guide, paste it at the top of the SKILL.md and the agent will use it as the dominant source of truth.
